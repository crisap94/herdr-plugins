# tab-recap — vocabulary

This is the plugin's ubiquitous language. **A word here means exactly one thing**, in the
code, the docs and the UI. `rules/recap-vocabulary.yml` rejects the banned synonyms in any
identifier, so a new name either uses this vocabulary or adds to it here first.

## The nouns

| Term | Means | Is NOT |
| --- | --- | --- |
| **Lane** | A herdr pane occupied by a recognised coding agent (`claude`, `codex`, `opencode`, and any kind the operator adds with `TAB_RECAP_SCREEN_AGENTS`), with the working directory (cwd) herdr reports for it, when it does. Lanes are what the columns follow; the *harness* below is what writes. **A recap never closes, resizes or moves a lane's pane** — whatever its title says. | any pane; a column |
| **Tab** | A herdr tab. **The unit of a recap column**: one tab, at most one column. | a workspace |
| **Cell width** | How many terminal cells a piece of text takes, counted per user-perceived character (a grapheme): terminal escape sequences 0, an emoji drawn with emoji presentation 2 (a ZWJ sequence or flag counts once), a combining mark 0, every other character 1. Layout (wrap, cut, footer fit) always uses cell width, never string length. East Asian wide characters are out of scope: no Node built-in reports them. | the string's `length` or its code points |
| **Column** | The recap pane the daemon docks in a tab, keeps sized and reopens. It has a **shape**: `side` (right edge, wide tabs) or `bar`. Recognised by its terminal title being EXACTLY `tab-recap` (side) or `tab-recap:bar` (bar), by hosting no agent and, when herdr reports it, the manifest label `Recap`; a lane that merely has a similar name is never a column. A column process replaces itself in place (`process.execve`: same pid, same terminal, so herdr sees no pane close) when the plugin's version on disk changes, seen on two looks in a row — an upgrade rolls the columns without closing them. | a *sidebar*, a *panel* |
| **Bar** | A column's phone shape: ONE row along the bottom of a narrow tab — 📝, a status dot per lane, one headline (what needs you, else what is happening now). A tap opens the modal. It is docked with a plain split below the tab's lowest pane, in any tab, focused or not: herdr can split only right or down (measured on 0.9.0: `up` and `left` are rejected), so a bar on top would need a pane swap, and a swap moves agent panes and the operator's focus. | a status line |
| **Modal** | The tab's **expanded view**, opened on demand as a herdr popup over everything; `q`/`Esc` closes it. The phone's view of a tab's recap, where a column does not fit. | a column; a notification |
| **Board** | The domain state: every lane, every column, the panes being closed, the reopen history. The only thing the fold changes. | herdr's session snapshot |
| **Turn** | One `working → rest` stretch of a lane. A turn **ends** when the lane leaves `working` for `idle`, `done` or `blocked`. | a message |
| **Transcript** | Where a lane's history is read from: the agent's own JSONL log (`~/.claude/projects/*/<session>.jsonl`, `~/.codex/sessions/**/rollout-*.jsonl`), opencode's SQLite database (`~/.local/share/opencode/opencode.db`, opened `readOnly`), or, for an agent with no readable store, its **screen**. Each source has one name that is unique to it (`<path>`, `<db>#<session>`, `screen:<pane>`). Read-only, always. | the recap |
| **Transcript registry** | The typed lookup that supplies the transcript reader for a known kind, or the screen reader for an unknown kind when that registry enables its fallback. The modal and replay each use a registry with their own explicit reader set. | a list of readers assembled at each call site |
| **Registered kind capability** | One explicit boolean on each key of `REGISTERED_KINDS` (`recap/domain/registered-kinds.ts`) stating whether it is compactable, in the default column policy, or autocompacted by default. The domain table derives these eligibility lists; the adapter reader table must cover the same closed `RegisteredKind` union. | the open branded `AgentKind` on a lane |
| **Screen** | What `pane.read` returns for a lane's pane: the text of its terminal, with the agent's chrome (borders, prompt, key hints) stripped. An agent on the alternate screen exposes only what is visible, so a screen is a coarser transcript: the column says `(screen)` beside it. Opt-in per agent kind (`TAB_RECAP_SCREEN_AGENTS=<list>\|all`), never typed into. | a screenshot; a transcript file |
| **Cursor** | Per lane: how far its transcript has been read into the tab's recap. **The reader owns what the number means**: a byte position for a JSONL file, the newest `time_updated` read for opencode, herdr's `revision` for a screen — with an optional **tail** (a hash of the last screen read, to tell a changed screen from a repainted one). The job only stores it and gives it back. A tab's recap holds one cursor per lane. | an *offset* (banned word) |
| **Live prompt** | The newest thing the operator typed to a lane, read from its transcript the moment the lane's status changes (a bounded tail read, through the lane's own reader) and published with the tab's view, so a lane's header never lags the conversation. It is separate from the recap's cursor: reading it moves nothing, and a lane with no readable transcript (a screen-read agent) simply has none. | the recap's *last prompt* field, which only moves when a recap is written |
| **Store** | The plugin's own state: one SQLite file, `tab-recap.db`, in the state directory, opened through four **repositories** — one per aggregate, each behind its own port: `RecapRecords` (a tab's history of runs and the recap read from the last good one), `TabViews` (what a column draws), `ColumnVisibility` (what the operator hid), `Requests` (what the columns ask of the daemon). The daemon, the columns, the commands and the setup modal all open it; only the daemon moves the old JSON files into it, once. Process files (`daemon.pid`, `daemon.beat`, `daemon.log`, `disabled`) stay files. | the agents' own transcripts; a cache |
| **Run** | One call of the writer for a tab: when, why (`turn-ended`, `focused`, `requested`, or `imported` for what the old files held), which backend, in what language, what it cost, and either the tasks and sections it produced or the error. A failed run keeps the recap of the last run that wrote one. The recap a column shows is the last good run's. | a turn; a recap |
| **Chapter** | A tab's stretch of history between two **boundaries**. Chapter 1 starts when the tab is first seen; every boundary seals the newest chapter and opens the next in the same transaction, and the run that follows belongs to the new one. `chapter_span` derives each chapter's end. The session facts count them (`chapters 3`). | a task; a run |
| **Boundary** | A break in a session, recorded from the agents' own records, never guessed: an agent **compacted** (Claude `compact_boundary`, Codex `compacted`, opencode's compaction answer), or a new transcript began in a pane that had one (**switched**, naming the transcript it replaces). It carries the record's own time, the tokens before and after when the record says them, and for a compaction its trigger — **plugin** when the plugin started a compaction of that lane in the ten minutes before it, else the agent's own word (**manual**: the operator typed it; **auto**: the agent's own), else **auto**. A boundary is recorded once: only marks newer than the lane's last boundary count. A compaction the plugin drove points at its boundary (`compaction.boundary_id`). The timeline draws it as a break line (`── compacted 800k → 14k ──`, `── new session ──`). | a compaction *record* (that is the plugin's own flow: stages, brief, outcome) |
| **Settled** | A fact closed before the lane's last boundary: the agent's own summary already holds it. The compaction brief marks it `settled="yes"` (a fact closed at or after the boundary, and every open fact, is not) and asks the writer to name settled facts in one line and not re-open them. | closed (a fact closes for a reason; settled is only about the boundary) |
| **Retention** | `TAB_RECAP_KEEP_DAYS` (default 30, `0` keeps everything): the daily upkeep removes a tab last seen longer ago than that and with no column open, with everything that belongs to it, one transaction per tab, logged with counts. A tab seen within the period is never touched. | a backup; the column hiding a tab |
| **Migration** | One numbered, forward-only step of the database's shape (`src/adapters/db/schema/NNN-name.ts`), applied inside one transaction by whichever process opens the file first; the number is `PRAGMA user_version`. A released one is never edited: a fix is a new number. | the one-time import of the old files (that is not numbered; the daemon does it once, tracked in `store_meta`) |
| **Backup** | The copy `tab-recap.db.v<n>.bak` made just before a migration upgrades a database from version n; the newest three are kept. What to restore when going back. | a copy of the state directory |
| **Id** | What names a row of the history (run, chapter, task, transcript, request): a UUIDv7 stored as 16 bytes, which carries only its creation time, shown at the edge as a TypeID — a short type prefix and 26 characters (`run_01h…`) that sort by time. A tab keeps herdr's own id (`w1:t3`). | a name or a counter |
| **Excerpt** | What is new in one lane's transcript since its cursor (for a screen: the screen, when it changed) — user prompts (marked when queued), agent replies, and bursts of tool calls with a kind — each with its time when the store records one. One `<transcript>` of the **Recap input** per lane. | the raw JSONL |
| **Recap input** | The one XML document (`recap_input`, version 2) the writer is given for a tab and a run: the tab and its agents (kind, label, pane, folder, repository, branch, recently edited files), the grouping in force, one **ledger** per task (its open facts and those closed in the last two hours, numbered `f1…fn`), the agents' own notes (away and compaction summaries — hints, the transcript wins) and one **excerpt** per lane, clipped to its beginning and end. Defined by `schema/recap-input.dtd`; generated by `recap/application/writer-context.ts` with the pure serializer `xml.ts` (no XML library); tests validate it with `xmllint --dtdvalid`. The instructions follow it. | prompt, context |
| **Recap** | What is written for one **task** — the lanes working on it as one piece of work — as seven fixed **sections**: Goal · Now · Needs you · Done · Decisions · Next · Links. The writer returns them as data (JSON), the plugin checks and caps them, and a renderer draws them. Kept as a **ledger** of **facts**: the column draws the newest open facts per section under the caps, the writer answers **operations**, nothing is rewritten. One per **task**; a tab with one task (the usual case) has one recap, never one per lane. | a *summary* (banned word); a per-agent note |
| **Task** | One piece of work inside a tab. A tab is not assumed to be one task: the plugin groups the tab's lanes by where they work (the git repository, else the folder) and keeps the grouping from run to run. A task has an id (kept while the grouping is kept), a name (blank when the tab has one task) and the lanes working on it, and holds ONE fixed recap (the seven sections). Lanes of one task share it; unrelated work gets one recap per task, often per lane. The column draws each task's lanes under its name, each followed by its recap; with one task nothing changes. | a tab; a lane |
| **Grouping** | Which lanes belong to which task. **Sticky** (`domain/grouping.ts`): the previous grouping stays. A lane that is new joins the task of the lanes in its place (repository, else folder), or becomes a task of its own, named by its folder; a lane of unknown place joins the first task; a lane that closes just leaves; a task left with no lane is gone (its facts stay in the ledger); when a tab's only task loses all its lanes, the next lanes continue it. | a re-run of the writer |
| **Claude recap** | Claude Code's own short recap (`system/away_summary` in the transcript). Shown only until our recap exists. | our recap |
| **Summarizer** | The port that turns a **recap input** (the ledger + what is new) into **operations** on the ledger. It is the **recap writer job** (`adapters/recap-writer.ts`) on one **harness**, picked by **backend**. | the daemon |
| **Harness** | A coding-agent CLI used as a text-in, text-out model (`ports/harness.ts`, one adapter each in `adapters/*-harness.ts`; the recap writer and the compaction brief are jobs on it):  `claude`, `codex`, `opencode`, `hermes`. Available when herdr's `integration.list` says so AND its program resolves on the daemon's PATH. Run tool-less and without keeping a session (flags where the CLI has them; otherwise the session is deleted after the answer). | a lane's agent kind; a backend |
| **Job harness registry** | The typed list in `recap/domain/backend.ts` that names each job harness and declares its model default, automatic selection, availability mark, custom command note, job contract and enumerator capability. Job harness ids and the lists shown to operators derive from it. | a transcript adapter registry |
| **Harness adapter** | Everything tab-recap knows about one kind of agent (`claude`, `codex`, `opencode`, or a screen-read kind), gathered as its sides: the **job side** (a **harness** it can run headless, where it has one), the **reader side** (its transcript, or its screen for a kind with no readable store), the **typing side** (what is typed to compact it) and the facts its records give (context, compaction marks, in-flight work). Today these sides are spread over several modules, and no single place names a kind's sides. | a lane's agent kind (the string); a harness on its own |
| **Conformance table** | `test/adapter-conformance.test.ts`: one row per kind, and the same expectations for every row (locate, read from the start and from its own position, latest prompt, observed, marks, in-flight work, compactable). A change to one kind's adapter is behaviour-preserving when its row still passes unchanged. Oddities a change may alter on purpose are marked `PINS TODAY:` where they are pinned. | a unit test of one function |
| **Backend** | The operator's choice of summarizer: `auto` (default: the first available of claude → codex → opencode → hermes, looked up at start and on every resync), a named harness, or `custom` (`TAB_RECAP_CUSTOM_CMD`: prompt on stdin, Markdown on stdout — never automatic). Each backend keeps its own model. | the agent kind of a lane |
| **Effort** | How hard the recap writer thinks: `low`, `medium` (default since 2.0: at `low` the writer records choices as open questions and no decisions, measured), `high` or `default` (pass nothing). `TAB_RECAP_EFFORT` and a settings row; each harness gets its own word (codex `model_reasoning_effort`, claude `--effort`, opencode `--variant` — `minimal` for low —, hermes `--reasoning`). Codex also runs with the features a recap never uses disabled. | thinking level, reasoning |
| **Locale** | The language of the plugin's own words — the column, the footer, the commands' messages: `en` or `es`. `TAB_RECAP_LOCALE=auto|en|es`; `auto` reads `LC_ALL`, then `LC_MESSAGES`, then `LANG`. Catalogs live in `src/i18n/`; `es` is typed as `Messages`, so a missing key fails the typecheck. | the recap language |
| **Recap language** | The language the recap itself is written in: `en`, `es` or free text (`Português`; letters, spaces, hyphens, ≤ 30 characters, ≤ 3 words). `TAB_RECAP_RECAP_LANG=ui|en|es|<name>`; `ui` follows the locale. Stored on each recap; when it differs from the wanted one the recap is rewritten at once, new excerpt or not. | the locale |
| **Section** | One of a task's recap's seven parts, always all seven, always in this order: `goal · now · needs · done · decisions · next · links` (Goal/Objetivo · Now/Ahora · Needs you/Te necesita · Done/Hecho · Decisions/Decisiones · Next/Siguiente · Links/Enlaces). The id is what the code means; the heading is what a language calls it. An empty section shows `—`. Recaps stored before the fixed structure keep their old Markdown headings (Waiting on you, Key refs, …) until their next rewrite. | a heading's text |
| **Cap** | The most a section may hold, enforced in code, not asked politely: Goal 1 line; Now 3, Needs you 3, Done 5, Decisions 3, Next 5, Links 6 bullets; at most 16 words per line, clipped with `…`. | a length setting (there is none) |
| **Compaction** | What the operator asks for with `tab-recap.compact` (or `c` in a column or the modal), or what **autocompact** asks for when it is `on` (same request path, same flow, **origin** `auto`): an agent that is idle or done is told what to keep while it compacts its conversation. A popup asks for an optional **focus note** (Enter sends, an empty note leaves no trace, Esc sends nothing; not when the **compact note** is `skip` or a `--note` is given, then it is queued at once); the daemon refreshes the recap (awaited, 90 s at most), then types once. **The agent never hears about the plugin:** the message is the operator's own instruction, first person, English, with no «recap», «tab», «plugin» or «tool» (a test asserts it over every template; a brief that names the plugin is refused). claude gets `/compact ` typed, then the guidance as ONE typed line, then Enter (`pane.send_text` twice + `pane.send_keys`: a pasted block, or a long single send, is taken as content and never runs the command); codex and opencode get their own `/compact` typed the same way (sent as a prompt it reaches them as a message, not a command — measured on codex), their records are read until they show the compaction (they compact on the spot, with no turn herdr pushes), then one message restoring where things stand, whose own turn is waited for so it never counts as the operator's next turn. A working or blocked agent is skipped and named in a notification. Only `src/adapters/herdr-agents.ts` names `agent.prompt`, `pane.send_text` and `pane.send_keys` (rule `recap-prompt-boundary`). `TAB_RECAP_COMPACT_TARGET`: `focused` (default), `all` or kinds. | the writer's recap |
| **Compaction record** | One row of the `compaction` table (migration 4, TypeID `cmp_…`): a compaction of one lane, written by the daemon at each step and only read by the column, the bar and the modal. It holds the **stage**, where the brief came from (written by a job, or the template and why), the times, the tokens before and after, whether it was retried and, when it did not happen, why. It stays on the lane until the agent's next turn (`dismissed_at`). A newer record of the lane replaces the shown one. | a toast; the `boundary` of the history |
| **Stage** | Where a compaction record stands: `briefing` (the brief job runs), `compacting` (the command is typed), `restoring` (codex/opencode: the restore message is sent, not yet answered) — all three in progress — then one end: `compacted` (the records confirm), `failed` (they say it failed, or typing failed), `unconfirmed` (the agent is free again and the records say nothing, or the daemon restarted) or `skipped` (the agent was busy). The lane header says the stage in the place of the `compact?` hint; the clock counts from when the stage began. | a status of the agent |
| **Brief** | What the agent's own summary must keep, written for one compaction by a model call (the **brief job**) from a **compaction input** and used as claude's `/compact` guidance and in the restore message of codex/opencode. At most 3 000 characters, one line, first person; vetted (no «recap», «plugin», «herdr», «tab») and, when it cannot be written, replaced by the template. | summary, prompt |
| **Compaction input** | The XML document (`compaction_input`, version 1; `schema/compaction-input.dtd`; `recap/application/compaction-input.ts`) the brief writer reads: the agent, the focus note, the latest recap as JSON, the **session history** and the agent's last turns (12 000 characters). | recap input |
| **Session history** | Every **fact** (open and closed, with its why, its reason for closing and its times) of the tasks that hold the agent's pane, newest last seen first, at most 300 (finished and closed facts are cut first). Read from the ledger (`Ledger.historyOf`); it is what the compaction brief is written from. | the story view |
| **Job** | One kind of model call — the recap writer, the compaction brief, the curator — run on a **harness** with a model and an effort (`Job {by, model, effort}`; `domain/job.ts`). Every harness (`claude`, `codex`, `opencode`, `hermes`, `custom`) is one `Harness.run({instructions, input}, {model, effort})` behind one port. The modal's **Models** group has a row per job. | backend, summarizer |
| **Rubric** | The yes/no checks a recap item must pass, in one file, `schema/recap-rubric.md`: seven item checks (I1 atomic · I2 stands alone · I3 specific · I4 supported · I5 about the work · I6 new · I7 still true) and one check per section, each with a pass and a fail example. The writer's instructions and the judge's instructions quote its item and section parts verbatim. | a prompt, a style guide |
| **Gate** | A pure function over one item of the writer's answer, no model call (`recap/domain/gates/`): it **refuses** (the operation goes back once, alone, in a **correction input** with the gate's reason, and is dropped if still refused) or **flags** (kept, counted). Since 2.1 only what would corrupt the ledger refuses (G1 narrator, G2 duplicate, G3 decision without a why, G6 unknown id, G10 close without a why, G11 anchor, G12 `answered` on a fact that is not a question); a link that is not a reference (G4), a wrong language (G5), vagueness (G8) and a pronoun opener (G9) flag. `gatekeeper.ts` runs them; the counts are the run's `gate_stats`. | a rubric check (a check is a question; a gate is a rule in code) |
| **Verdict** | One stored answer of the judge or the operator: a run, an item (`<task>/<section>/<position>`, none for a run-level check), a check id (`I1`…`I7`, `S-<section>`, `coverage`, `filler`, `readback-<n>`; `state/…` keys for the ledger-state rows, see **State (judging)**), pass or fail, a one-line critique when failed, who judged, and the source (`judge` or `operator`). | a gate count |
| **Judge** | The job (`TAB_RECAP_JUDGE_BY/_MODEL/_EFFORT`, default: the recap writer's harness and model at medium effort) behind `tab-recap eval`: it scores stored runs against the rubric, extracts the key facts of the input and measures coverage and no-filler, and runs a read-back from the recap alone. Calibrated against the operator's own verdicts (`eval --label`, `--agree`). | the writer, a reviewer |
| **State (judging)** | The ruler the judge measures **coverage**, **no-filler** and the **read-back** with since 2.1: the task's facts that were open right after the run (`born_run <= run` and not closed before the run's time), keyed `state/<task>/<section>/<n>` in a verdict. The item checks (I1–I7, S-<section>) are scored once, over the facts the run **added** (keyed `<task>/<section>/<n>`). A report shows the state numbers first and the added numbers beside them. | the run's additions; the recap column |
| **Anchor** | A short quote (at most 120 characters) copied from the writer's input that an added fact comes from — a turn, a tool call or an agent note. Gate G11 refuses an `add` whose anchor is empty or not found in the input after whitespace folding (words by `Intl.Segmenter`, case kept); stored as `fact.anchor` (migration 9, nullable: facts imported from 1.x have none). A fact with a verified anchor that the judge calls unsupported is listed as "judge vs anchor". | a link; the fact's `ref` |
| **Candidate** | A fact the **enumeration** found in a chunk of turns and has not yet reconciled with the ledger: a section, a text, an optional why and reference, a time and its anchor. Candidates are the only source of `add` operations in the pipeline; the open ledger is the only source of ids. | a fact (a candidate has no id and is not stored) |
| **Enumeration** | The first step of the pipeline: a low-effort call per chunk of new turns that lists, per section, every candidate with its anchor, or `none`; triggers (a commit, an edit, an error, a question to the operator) add mandatory stubs it must fill or skip with a reason. `enumerate_input` (`schema/enumerate-input.dtd`). | the writer's single call of 2.0 |
| **Reconciliation** | Matching **candidates** and the open ledger into operations (`add`, `update`, `close`), and, separately, the curator's review of the open ledger against the transcript tail (updates and closes, never adds) every N turns, on an open of the expanded view and after a compaction. | a **gate** |
| **Correction input** | The short document of the one retry (`correction_input`, `schema/correction-input.dtd`): the operations a gate refused with their reasons and anchors, and the open facts they name — no transcript. The writer answers replacements for those operations only. | the full `recap_input` of a first try |
| **Focus note** | The one line the operator may type in the compaction popup; the first priority of the message («Above all, keep: …»), never trimmed. | a recap section |
| **Compact note** | `TAB_RECAP_COMPACT_NOTE` (`ask` by default, or `skip`; the settings row «Compact note») and `tab-recap compact --note "<text>"`: whether `compact` opens the focus-note popup first. `ask` opens it; `skip` and a `--note` queue the compaction at once with no popup (the note is `null` for `skip`, the text for `--note`). `c` in a column follows the same setting. | the focus note (the text itself) |
| **Rules** | The recap writer's eighth list (≤ 5 lines of ≤ 16 words): standing constraints the operator stated. Stored (`item.section='rules'`, migration 3), sent in a compaction, never drawn in the column — only the **expanded view** draws them. | one of the seven sections |
| **Fact** | One line of a task's recap that has an identity: an id, a **section**, a text of at most 16 words, a why (required for a decision), an optional reference and agent, when it was first and last seen, its state (`open` or `closed`), why and when it closed (`done`, `wrong`, `superseded`, `answered`, `merged`, `rewritten`), the runs that created and last touched it, and its language. A fact is never deleted by a run; it is closed with a reason. `goal` is one open fact per task. When a run applies operations, every open `now` fact of the task that the run did not add, update or close is closed `superseded` at the run's time (now is what is under way at recap time); a run with no operations closes nothing. Stored in `fact` (migration 6). | a recap *item* of 1.x (no id, no time, no reason) |
| **Operation** | What the writer answers since 2.0: `{"ops":[…]}`, each `add` (a new fact), `update` (a fact's text or why) or `close` (a fact, with a reason). Applied in one transaction per run, closes first, then updates, then adds; an operation on an unknown id, on a closed fact, a `close` without a why or a second `goal` is **refused** (and sent back once as a correction). | a rewrite of the whole recap |
| **Ledger** | The facts of one task, open and closed, and the port that keeps them (`src/ports/ledger.ts`): `openOf`, `recentlyClosed`, `apply`, `allOf`, `historyOf`. The writer is given the open facts (and those closed in the last two hours) as `<ledger>` in the version 2 **recap input**, each with a document id `f1…fn`; the column draws the newest open facts per section under the **caps** (a view rule, not a storage rule). | the *session history* of 1.x (distinct lines folded from runs) |
| **Context use** | How full a lane's conversation is: tokens in use (claude: the newest assistant row's `usage`; codex: the newest `token_count`; opencode: the newest assistant message's `tokens`) against the **window**, found at runtime and published with the tab's view. | a cost |
| **Window** | The tokens a model can hold, measured against in this order: `TAB_RECAP_CONTEXT_WINDOW` (operator, overrides); what the agent states (codex rollout `model_context_window`); opencode's local models.dev catalogue `~/.cache/opencode/models.json` (`limit.context`, read-only, never fetched); for claude a built-in family fallback table; and raised to the next known size (200 000 → 1 000 000) when more has been seen in use (or before a compaction, `preTokens`). The lane header says `compact? 45% of 1M` from `TAB_RECAP_COMPACT_HINT` percent (default 40; `off`, or 10–95). Advisory: the hint never starts a compaction (autocompact is its own setting). | the model's output limit |
| **Autocompact** | The plugin deciding by itself that a lane should be compacted: on an agent's `idle`/`done` push, code **gates** (kind, nothing in progress, nothing **in flight**, share at or above the **minimum**, cooldown, **unchanged**, **ceiling**) then a **decider** answers typed yes/no questions about the last turns. `TAB_RECAP_AUTOCOMPACT=off\|shadow\|on`, `shadow` by default (records, never requests). On requests the same compaction as the operator, with origin `auto`. | a hint; a setting of the agent's own auto-compaction |
| **Decision (autocompact)** | One row of `autocompact_decision` (migration 10): a lane, the instant, the mode, the share, the gate that decided, the answers by question id, the brief **coverage**, the decider, its cost and time, and the verdict (`compact`, `wait`, `undecided`, `unknown`). Written only for a consideration that passed the minimum. | a compaction record |
| **Decider** | The port (`ports/decider.ts`) that answers a set of typed yes/no questions with probabilities over one JSON state: `JevDecider` (TypeSafe System One, bearer key never shown) or `HarnessDecider` (one `Harness.run`). | **Minimum** | The context share (`TAB_RECAP_AUTOCOMPACT_AT`, 10, 10–95) from which a lane is evaluated: below it nothing is asked, above it every safe moment compacts. | the hint percentage (`TAB_RECAP_COMPACT_HINT`) |
| **Sweep** | The daemon's pass over the idle and done lanes of the board: shortly after its start, then every five resync ticks (`SWEEP_EVERY`). One **consideration** at a time, each through the same gates; a lane is asked again only when something changed since its last decision (its tokens, the mode, or a restart). A sweep still running is not stacked. | a poll of the agents |
| **Skip (autocompact)** | The latest gate that stopped a lane's consideration: `below-minimum`, `busy`, `in-flight`, `cooldown`, `unchanged` or `no-context`. One row per lane of `autocompact_skip`, replaced at each skip and removed when the lane gets a decision; the log names a skip only when its gate changed. | a decision |
| **Ceiling** | The share (`TAB_RECAP_AUTOCOMPACT_CEILING`, above the minimum; unset, the **autocompact style**'s: 80 with `balanced`) at which the verdict is `compact` with no model call. | the window |
| **Autocompact style** | One setting, `TAB_RECAP_AUTOCOMPACT_STYLE` (`gentle`, `balanced` (default), `eager`), that sets the verdict's warning and close numbers, the undecided band, the brief check's pass mark, the ceiling and the cooldown when their keys are unset, and the **re-check**. Explicit keys win over it (`…_CEILING`, `…_COOLDOWN_MS`, and the advanced `…_SAFE_AT_MOST`, `…_CLOSES_AT_LEAST`, `…_COVERAGE_AT_LEAST`, `…_RECHECK_IDLE_MS`). | a mode (`off`/`shadow`/`on`) |
| **Re-check** | The interval (`eager`, or `TAB_RECAP_AUTOCOMPACT_RECHECK_IDLE_MS`) after which an idle lane whose last decision was `wait` (or `undecided`) at unchanged tokens is asked again: the `unchanged` gate lets it through once it has been idle that long since that decision. A `compact` decision is never re-asked. Each re-check is one decider call, in `shadow` too, so an idle eager lane costs one call per interval for as long as it stays idle. The log says `unchanged → recheck`. Never bypasses busy, minimum, cooldown or in flight. | a change of tokens |
| **In flight** | Work a free agent has started and not ended: a background shell, an Agent/Task launch or a Monitor with no `<task-notification>` that ended it (`Transcripts.inFlight`; claude only; a reader that cannot tell is `Unknown`, treated as in flight). The Claude reader reads further back, doubling its budget up to 16 MB, while the tail ends work it never saw launched. | a working agent |
| **Brief coverage** | After the brief is written: per open fact of the lane's tasks, whether the brief keeps it (and, for a decision, its reason). A missing goal, need, decision or rule gets one rewrite, then an autocompact waits. Its decider is `TAB_RECAP_AUTOCOMPACT_COVERAGE_BY`: `auto` (the default: Jev when a key is found, else the moment decider), `jev` or `decider`. | the brief's length |
| **Origin** | Who started a compaction: `operator`, `auto` or `request` (another tool's `compact-req-<tool>`; `compaction.origin`). Shown as `(auto)` in the toast. | the boundary's **trigger** |
| **Setup modal** | The settings popup (`tab-recap.configure`): rows for the agent (harness or `auto`), its model, the interface language, the recap language and the agents read from their screen; `t` tests the selected agent with one tiny real request, `s` saves to `config.env`. A row an environment variable overrides is read-only and names the variable. Opening it while herdr shows another modal fails with `ui_busy`; the command then prints the CLI equivalent. | the recap modal (`show`) |
| **Hidden** | A tab whose column the operator turned off (`tab-recap.column`, or `h` in the column). It is closed, not reopened, and never counts against the reopen budget; its recaps keep being written. `tab-recap.columns` hides every tab at once; showing one tab again under that blanket exempts it. Remembered in the store (`ColumnVisibility`) and restored at daemon start. | closed by the operator's mouse (that is *given up*) |
| **Extension** | An optional add-on registered in `src/extensions/index.ts` (`FACTORIES`; the built-in git note and the other tools' notes are the entries by default). It may contribute notes, a warning and upkeep; the plugin works with none. Built once when a process starts; it reads its own settings through the config getter at call time, so a value edit applies without a restart, but enabling or disabling one takes a restart. | a plugin; a backend |
| **Note** | One labelled line-group an extension attaches to a lane; the column shows it under the lane's header (`⚑ label 2m ago · detail · detail`). It may carry its own **mark** (the glyph before the label, `⚑` when it names none). An extension's `notes()` may receive the tab's lanes and the locale. | a notification we send |
| **Repo** | Which git repository (top-level directory) and branch a lane's working directory belongs to, asked from git by the `LaneRepo` port: a repo (the branch is null on a detached HEAD), no repo, or unknown. Read-only (no optional locks, no fsmonitor), answered asynchronously and cached for a few seconds per directory. | the lane's cwd itself |
| **Web context** | Where a lane's repository lives on the web: the `origin` remote turned into `https://host/group/repo` (`git@host:g/r.git` and `ssh://git@host:2222/g/r.git` → https, `.git` dropped, **credentials never stored or drawn**), the forge (`github` for github.com, `gitlab` for any other host) and the lane's branch (null on a detached HEAD). Asked of git by the daemon only (`LaneRepo`, cached with the repo; the column never runs git), kept in the lane's row (migration 2) and published with the tab view as `TabLane.web` (null without an `origin`). A task has one web context when its lanes that know theirs agree on the repository; otherwise none, and only full URLs link. | the lane's cwd; a link |
| **Link** | A reference in a recap drawn as an OSC 8 hyperlink that keeps its short visible name: a full `http(s)` URL, `!N` (GitLab merge request), `#N` (GitHub pull request, GitLab issue), a commit SHA (7–40 hex with a digit and a letter), a branch name and a repository file path (`src/a.ts`, `src/a.ts:12`; branches and paths need backticks). Resolved at draw time from the task's **web context** (`render/links.ts`, pure), drawn by `render/hyperlink.ts`: zero cells, closed and reopened on every line a wrapped link spans, refused when the URL holds a control character; `NO_COLOR` keeps them. herdr opens them on Ctrl-click. | an *OSC 8 sequence* in the writer's text (the writer writes plain names) |
| **Git note** | The built-in extension's note under a lane: `⎇ <branch> · N unpushed · M changed` (`⎇ <rama> · N sin subir · M cambiados`), from `git status --porcelain=v2 --branch` in the lane's cwd. Unpushed = commits ahead of the upstream (absent without one); changed = tracked changes, conflicts and untracked files. Nothing outside a repository. Read from a cache: a refresh runs asynchronously, read-only (no optional locks, no fsmonitor), 1.5 s timeout, and is repeated when the worktree's HEAD or index changes or after 5 s. `TAB_RECAP_GIT_NOTE=on|off` (default on), read at call time. | a recap section; the lane's own title |
| **Expanded view** | What the modal and `tab-recap.show` draw: the whole ledger of a tab, with no model call to wait for — Goal · Now · Needs you (each with how long it has waited, oldest first) · Timeline (done facts and every closed fact, newest first, `HH:MM text`, a date line when the day changes, `· closed: why` on a fact that closed without being done) · Decisions with their why on the next line · Next · Rules · Links · **Session facts**. From 140 cells wide (`EXPANDED_TWO_COLUMNS`) two columns of `(width − 3) / 2` cells with a gray `│` gutter, scrolled together as zipped rows; narrower, one column in that order. A region with nothing in it is not drawn. Pure layout (`render/expanded.ts`, `expanded-regions.ts`, `timeline.ts`), fed by `application/expanded-view.ts`. The column, the bar, the keys and the phone's one-column layout are unchanged. | the column made wider; a recap |
| **Context window source** | The adapter-provided basis for a lane's context size: an observed value, a model catalogue entry, a Claude family table, or the operator's setting. The domain applies setting priority and raises undersized values to cover observed peak usage. | the current model; a transcript |
| **Session facts** | The lines at the end of the expanded view that are computed from the store and never written by a model: when the tab was first seen and for how long, runs by cause (`turn · focus · asked`; imported runs are not counted), the compactions that finished with their tokens before → after, each agent's share of its context window, the repository and branch, the files edited most (counted from the lanes' own records, the most recent 4 MB of each, read-only). A fact that is not known leaves its line out — never a guess. `domain/session-facts.ts` (pure) and `render/session-lines.ts`. | a recap section |
| **Herdr events** | `TAB_RECAP_HERDR_EVENTS` (`off` by default, or `on`; the settings row “Herdr events”): whether tab-recap shares anything on herdr's event stream. Off, it writes no lane token and no event, and answers no compaction request; it still honours other tools' leases and `awaiting` tokens. | a switch for the column or the recaps |
| **Lane token** | A pane token tab-recap writes on a lane's pane through `pane.report_metadata`: `tab-recap-api` (the protocol version, `1`), `tab-recap-share` (the context share in percent), `tab-recap-recap` (epoch ms of the last recap) and `tab-recap-needs` (the open needs). Written only on change or at half its time to live (2 minutes), cleared when the lane leaves the board. | a message to a tool; a fact the store keeps |
| **Token owner** | The one writer of a token name, and the writer's name is in it: `tab-recap-*` and `typing-tab-recap` are tab-recap's; `compact-req-<tool>`, `typing-<tool>`, `awaiting-<tool>` and `note-<tool>` belong to `<tool>`. herdr merges every source into one flat map per pane, so the name is the only protection: tab-recap never writes or clears a name it does not own. | a herdr `source` (herdr does not keep writers apart) |
| **Joined request** | A compaction request (any origin) for a lane whose compaction is already queued or in progress: it starts nothing, is answered `queued`, then with the running compaction's stages and outcome. One compaction per lane is the rule; the lane's **claim** (`CompactionClaims`, in process) is what the joined request waits on. | a second compaction |
| **Compaction request** | A `compact-req-<tool>` token written by another tool on a lane's pane, valued `<id>` or `<id>:<note>`. tab-recap queues it with origin `request` and answers in `tab-recap-compact` = `<id>:<stage>` (`queued`, `running`, `done`, `failed-<reason>`, `failed-not-a-lane`); each id is acted on once. | a command; a typed line |
| **Typing lease** | `typing-<tool>` = an epoch stamp, held by whoever types into a pane while it types (tab-recap's is `typing-tab-recap`, time to live 60 s). A lease that is earlier than tab-recap's, and still live, defers tab-recap's brief. | a lock on the pane; a process |
| **Ask (another tool's)** | A compaction request from another tool, `compact-req-<tool>`, identified by its (tool, id). Kept in the `compact_ask` table (migration 13) so an id is acted on once, across restarts. | an operator's request (the `request` queue); the ask-back of a run |
| **Note (from another tool)** | A `note` or `note-<tool>` token on a lane's pane, shown under the lane's header, labelled with the tool's name (or `note`). Read only: tab-recap never writes one. | a recap note; a fact |
| **Protocol version** | `tab-recap-api` (`1`): the version of the pane tokens above. A breaking change to a token's name or value format raises it; a tool that finds no `tab-recap-api` on a pane reads it as “not offered”. | the plugin's version |
| **Story** | The curator's "session so far" paragraph of a task (at most 120 words, shown at the top of the expanded view with its time): `task.story_text` and `task.story_at` (the time its curator run began), written in the same transaction as the curator's merges. | the recap; a section |
| **Curator** | The **job** that runs when the expanded view opens and a task's ledger changed since its story was written (the view asks through the request queue, kind `curate`; the daemon runs one call per task, at most once per 5 minutes): it may close a fact as `merged` into another open fact and it writes the **story**. Any other operation it answers is refused and logged; the story is stored whatever else was refused. The view never waits for it: it shows the last story and `updating…`. Its Models row is `TAB_RECAP_CURATE_BY` / `_MODEL` / `_EFFORT` (default: the recap writer's harness, medium effort). The operator reads its output, so the plugin's own words are allowed in it. `application/curate.ts`, `domain/curation.ts`, `schema/curator-input.dtd`. | the recap writer; a compaction brief |
| **Chunk** | The part of a run's new turns that one enumeration call reads: at most 6 000 characters of markup, split between turns and, inside a long turn, only between bursts of tool calls (`application/chunking.ts`). Not the reader's `Chunk` (what a transcript read returned). | a chunk of a transcript read |
| **Trigger** | An event a coding session is made of, found with no model in the structured tool calls and the turns (`application/triggers.ts`): a command that makes history (`git commit\|merge\|push\|tag`, `gh pr\|release`, `glab mr`), an edit, an error (`Error`, `FAIL`, `✖`, `Traceback`), a question. Each becomes a **stub** the enumeration must fill in as a **candidate** or skip with a reason; a stub it ignores is kept as a flagged candidate. | a hook, a gate |
| **Ask-back** | The bounded second look of a run (`application/ask-back.ts`): when its turns took more than one chunk, or it read at least 2 000 characters and found fewer than one candidate per 2 000, the six read-back questions that no candidate answers (and what changed about the open facts the turns mention) drive ONE more enumeration, restricted to them. Never a third call. | a retry |
| **Pipeline** | The steps a run's new turns go through to become operations (`recap/domain/pipeline.ts`, `TAB_RECAP_PIPELINE`, `eval --replay --pipeline`): `one` (the single call of 2.0), `enumerate` (the enumeration, then the writer reconciles the candidates), `enumerate+gates` (the same with the recall-first gates), `full` (also the ask-back). Every replay report names the pipeline, the writer and the judge. | a job (a job is one kind of model call) |
| **Reconcile mode** | The curator's second kind of call (`application/ledger-reconcile.ts`, `TAB_RECAP_RECONCILE_EVERY`, default 8 turns; also at an open of the expanded view that follows new turns, and on the first run after a boundary; at most once per 5 minutes per task): its input is the task's open facts, the rubric's *still true* check and the newest turns (`<tail>`, the evidence); it may update a fact, close it (done, wrong, superseded, answered — answered only a *needs* fact) or merge it, never add; every update and close but a merge carries a quote of the tail, so a fact is never changed for what a summary leaves out. Its operations pass the writer's gates. `domain/reconciliation.ts`. | the curator's story call |
| **Upkeep** | The housekeeping an extension does on the daemon's resync tick. The column never runs it. | a recap job |
| **Host** | The machine and runtime the plugin runs on: the Node version, the path of the `node` that ran, the OS family (`macos`, `linux`, `windows`) and the PATH, read through the `Host` port (`src/host/node-host.mjs`). **Supported** means Node ≥ 24.21.0 (`src/host/policy.mjs` is the one place that number lives); when it is not, the policy answers with what was found, what is needed and the fix steps **for that OS**. Everything else that differs by OS goes behind a port with one adapter per OS family — `ProcessControl` (run a program, end its whole tree), `ConfigPaths` (default config and state directories) — chosen once at a composition root; only `src/host/` and the `*-posix`/`*-windows`/`*-xdg` adapters may probe the OS (rule `recap-host-probes-at-the-edge`). Windows adapters exist and are tested with fakes; the manifest does not declare Windows yet. | the lane's machine; a backend |
| **Launcher** | The tiny plain-JavaScript file herdr (or the daemon spawn) runs first — `bin/tab-recap.mjs`, `src/column/launch.mjs`, `src/setup/launch.mjs`, `src/compact/launch.mjs`, `src/daemon/launch.mjs`. It reads the **host**, asks the policy and only then `import()`s the TypeScript entry (no TypeScript syntax, no static import of a `.ts`: a Node that cannot run TypeScript must still be able to say so). On an unsupported host a **pane** (column, settings, compaction) shows the refusal and stays until SIGTERM, the **daemon** logs one dated line and exits 1, a **command** prints it to stderr and exits 1 — except `status`, which loads its entry and reports. The refusal speaks the operator's language when the catalogs load, English otherwise. | the composition root (`main.ts`) it loads |
| **Daemon** | The one long-running process: watches herdr, folds observations, dispatches intents. On stop it closes every column in ONE batch (one look at herdr) and waits for it, up to 15 s, before exiting. It beats once a second (`daemon.beat` in the state dir); `ensure`/`start` replace a daemon that is alive but has not beaten for 3 minutes, and the informer subscribes afresh after 5 minutes without a frame or a snapshot. It publishes the plugin version it was **started with** in every tab view; the column ends its meta line with the version of the code on disk (`· v1.5.0`) and, when the two differ, says in yellow `daemon v1.4.1 — restart` (a daemon too old to say shows `v?`). | a *worker* (banned word) |

## The verbs of the fold

| Term | Means |
| --- | --- |
| **Observation** | Something herdr (or the operator) told us: `detected`, `closed`, `status`, `reconciled`, `column-opened`, `column-failed`, `focused`, `requested`, `switched`, `visibility`, `hidden-restored`. The fold's only input. |
| **Intent** | Something the board now wants done: `open-column`, `close-column`, `recap` (of a tab, carrying all its lanes), `publish`, `save-hidden`, `give-up`. The fold's only output. Dispatch turns intents into port calls. |
| **Watch set** | The herdr subscriptions the daemon holds: the global topics plus one `pane.agent_status_changed` per lane. Lives in exactly one file, `watch-set.ts`. |
| **Reconcile** | Replace the board's picture of herdr with a fresh snapshot. A subscription delivers *changes*, never the present, so the snapshot always comes after subscribing. A snapshot is stamped with when it was *requested*: a column opened after that cannot be in it, so its absence is not "gone". Two of our columns in one tab are healed by closing the extra. A refresh of an already-subscribed daemon (the minute tick, a `resync` frame) takes only the snapshot; a new subscription is opened when the watch set changes, the stream ends, or on every 10th tick. |
| **Publish** | Write a tab's view (its lanes and their statuses) for its column to render. |
| **Reopen budget** | How often a column may be reopened after being closed: 3 times in 2 minutes, then the tab is **given up** for 10 minutes. Stops the daemon fighting an operator who means it. A close the daemon asked for and herdr has not done after 30 s (the **close grace**) is asked again and counts against the budget too. |

## Rules the terms carry

Facts about a term that a reader needs and that no name or test states.

### Store
- **Last seen** (Retention): a tab's last seen is the newer of its last run and the last time the daemon drew its column, so a tab whose column was drawn recently is never removed whatever its last run says.

### Boundary

- A boundary's tokens before and after come from the agent's mark when it carries them, else from the compaction record the plugin wrote for it.

### Gates
- **Gate `L`** is not a function in `recap/domain/gates/`: it labels the refusals of the ledger's own rules (a second `goal`, an update of a closed fact), found by a dry run of the fold against the facts the document showed. They are reported and sent back in the one retry like a gate's refusal, so everything that would be refused is known before anything is written.

## Banned synonyms

`summary` → **recap** · `sidebar`, `panel` → **column** · `offset` → **cursor** ·
`worker` → **daemon**. Words that come from the outside world (`away_summary`, a herdr field)
appear only as **string literals** at an adapter's edge, never as our identifiers.
