# tab-recap — vocabulary

This is the plugin's ubiquitous language. **A word here means exactly one thing**, in the
code, the docs and the UI. `rules/recap-vocabulary.yml` rejects the banned synonyms in any
identifier, so a new name either uses this vocabulary or adds to it here first.

## The nouns

| Term | Means | Is NOT |
| --- | --- | --- |
| **Lane** | A herdr pane occupied by a recognised coding agent (`claude`, `codex`, `opencode`, and any kind the operator adds with `TAB_RECAP_SCREEN_AGENTS`), with the working directory (cwd) herdr reports for it, when it does. Lanes are what the columns follow; the *harness* below is what writes. **A recap never closes, resizes or moves a lane's pane** — whatever its title says. | any pane; a column |
| **Tab** | A herdr tab. **The unit of a recap column**: one tab, at most one column. | a workspace |
| **Cell width** | How many terminal cells a piece of text takes, counted per user-perceived character (a grapheme): terminal escape sequences 0, an emoji drawn with emoji presentation 2 (a ZWJ sequence or flag counts once), a combining mark 0, every other character 1. Layout (wrap, cut, footer fit) always uses cell width, never string length. East Asian wide characters are out of scope: no Node built-in reports them. | the string's `length` or its code points |
| **Column** | The recap pane the daemon docks in a tab, keeps sized and reopens. It has a **shape**: `side` (right edge, wide tabs) or `bar`. Recognised by its terminal title being EXACTLY `tab-recap` (side) or `tab-recap:bar` (bar), by hosting no agent and, when herdr reports it, the manifest label `Recap`; a lane that merely has a similar name is never a column. A column process replaces itself in place (`process.execve`: same pid, same terminal, so herdr sees no pane close) when the plugin's version on disk changes, seen on two looks in a row — an upgrade rolls the columns without closing them. | a *sidebar*, a *panel* |
| **Bar** | A column's phone shape: ONE row along the bottom of a narrow tab — 📝, a status dot per lane, one headline (what needs you, else what is happening now). A tap opens the modal. It is docked with a plain split below the tab's lowest pane, in any tab, focused or not: herdr can split only right or down (measured on 0.9.0: `up` and `left` are rejected), so a bar on top would need a pane swap, and a swap moves agent panes and the operator's focus. | a status line |
| **Modal** | The same view as a column, opened on demand as a herdr popup over everything; `q`/`Esc` closes it. The phone's view of a tab's recap, where a column does not fit. | a column; a notification |
| **Board** | The domain state: every lane, every column, the reopen history. The only thing the fold changes. | herdr's session snapshot |
| **Turn** | One `working → rest` stretch of a lane. A turn **ends** when the lane leaves `working` for `idle`, `done` or `blocked`. | a message |
| **Transcript** | Where a lane's history is read from: the agent's own JSONL log (`~/.claude/projects/*/<session>.jsonl`, `~/.codex/sessions/**/rollout-*.jsonl`), opencode's SQLite database (`~/.local/share/opencode/opencode.db`, opened `readOnly`), or, for an agent with no readable store, its **screen**. Each source has one name that is unique to it (`<path>`, `<db>#<session>`, `screen:<pane>`). Read-only, always. | the recap |
| **Screen** | What `pane.read` returns for a lane's pane: the text of its terminal, with the agent's chrome (borders, prompt, key hints) stripped. An agent on the alternate screen exposes only what is visible, so a screen is a coarser transcript: the column says `(screen)` beside it. Opt-in per agent kind (`TAB_RECAP_SCREEN_AGENTS=<list>\|all`), never typed into. | a screenshot; a transcript file |
| **Cursor** | Per lane: how far its transcript has been read into the tab's recap. **The reader owns what the number means**: a byte position for a JSONL file, the newest `time_updated` read for opencode, herdr's `revision` for a screen — with an optional **tail** (a hash of the last screen read, to tell a changed screen from a repainted one). The job only stores it and gives it back. A tab's recap holds one cursor per lane. | an *offset* (banned word) |
| **Live prompt** | The newest thing the operator typed to a lane, read from its transcript the moment the lane's status changes (a bounded tail read, through the lane's own reader) and published with the tab's view, so a lane's header never lags the conversation. It is separate from the recap's cursor: reading it moves nothing, and a lane with no readable transcript (a screen-read agent) simply has none. | the recap's *last prompt* field, which only moves when a recap is written |
| **Store** | The plugin's own state: one SQLite file, `tab-recap.db`, in the state directory, opened through four **repositories** — one per aggregate, each behind its own port: `RecapRecords` (a tab's history of runs and the recap read from the last good one), `TabViews` (what a column draws), `ColumnVisibility` (what the operator hid), `Requests` (what the columns ask of the daemon). The daemon, the columns, the commands and the setup modal all open it; only the daemon moves the old JSON files into it, once. Process files (`daemon.pid`, `daemon.beat`, `daemon.log`, `disabled`) stay files. | the agents' own transcripts; a cache |
| **Run** | One call of the writer for a tab: when, why (`turn-ended`, `focused`, `requested`, or `imported` for what the old files held), which backend, in what language, what it cost, and either the tasks and sections it produced or the error. A failed run keeps the recap of the last run that wrote one. The recap a column shows is the last good run's. | a turn; a recap |
| **Chapter** | A tab's stretch of history between two breaks in a conversation. **Until 1.7 a tab has chapter 1 only**: the table is there, nothing opens a second one yet. | a task; a run |
| **Migration** | One numbered, forward-only step of the database's shape (`src/adapters/db/schema/NNN-name.ts`), applied inside one transaction by whichever process opens the file first; the number is `PRAGMA user_version`. A released one is never edited: a fix is a new number. | the one-time import of the old files (that is not numbered; the daemon does it once, tracked in `store_meta`) |
| **Backup** | The copy `tab-recap.db.v<n>.bak` made just before a migration upgrades a database from version n; the newest three are kept. What to restore when going back. | a copy of the state directory |
| **Id** | What names a row of the history (run, chapter, task, transcript, request): a UUIDv7 stored as 16 bytes, which carries only its creation time, shown at the edge as a TypeID — a short type prefix and 26 characters (`run_01h…`) that sort by time. A tab keeps herdr's own id (`w1:t3`). | a name or a counter |
| **Excerpt** | What is new in one lane's transcript since its cursor (for a screen: the screen, when it changed) — user prompts (marked when queued), agent replies, and bursts of tool calls with a kind — each with its time when the store records one. One `<transcript>` of the **Recap input** per lane. | the raw JSONL |
| **Recap input** | The one XML document (`recap_input`, version 1) the writer is given for a tab and a run: the tab and its agents (kind, label, pane, folder, repository, branch, recently edited files), the grouping in force, the previous recap, the agents' own notes (away and compaction summaries — hints, the transcript wins) and one **excerpt** per lane, clipped to its beginning and end. Defined by `schema/recap-input.dtd`; generated by `recap/application/writer-context.ts` with the pure serializer `xml.ts` (no XML library); tests validate it with `xmllint --dtdvalid`. The instructions follow it. | prompt, context |
| **Recap** | What is written for one **task** — the lanes working on it as one piece of work — as seven fixed **sections**: Goal · Now · Needs you · Done · Decisions · Next · Links. The writer returns them as data (JSON), the plugin checks and caps them, and a renderer draws them. Rolling: each new recap is the previous one plus the latest excerpt. One per **task**; a tab with one task (the usual case) has one recap, never one per lane. | a *summary* (banned word); a per-agent note |
| **Task** | One piece of work inside a tab. A tab is not assumed to be one task: the writer groups the tab's lanes into tasks in the same call that writes the recap, using each lane's hints (cwd, repo, branch, title, files touched). A task has an id (kept while the grouping is kept), a name (blank when the tab has one task) and the lanes working on it, and holds ONE fixed recap (the seven sections). Lanes of one task share it; unrelated work gets one recap per task, often per lane. The column draws each task's lanes under its name, each followed by its recap; with one task nothing changes. | a tab; a lane |
| **Grouping** | Which lanes belong to which task. **Sticky**: the previous grouping stays unless the writer marks a change with evidence (`regroup`: e.g. the two lanes now work in different repos). A lane that is new joins a task freely; a lane that closes just leaves. | a re-run of the writer |
| **Claude recap** | Claude Code's own short recap (`system/away_summary` in the transcript). Shown only until our recap exists. | our recap |
| **Summarizer** | The port that turns a **recap input** (previous recap + what is new) into a new recap. One adapter per **harness**, plus `custom`; picked by **backend**. | the daemon |
| **Harness** | A coding-agent CLI that can write the recap: `claude`, `codex`, `opencode`, `hermes`. Available when herdr's `integration.list` says so AND its program resolves on the daemon's PATH. Run tool-less and without keeping a session (flags where the CLI has them; otherwise the session is deleted after the answer). | a lane's agent kind; a backend |
| **Backend** | The operator's choice of summarizer: `auto` (default: the first available of claude → codex → opencode → hermes, looked up at start and on every resync), a named harness, or `custom` (`TAB_RECAP_CUSTOM_CMD`: prompt on stdin, Markdown on stdout — never automatic). Each backend keeps its own model. | the agent kind of a lane |
| **Effort** | How hard the recap writer thinks: `low` (default), `medium`, `high` or `default` (pass nothing). `TAB_RECAP_EFFORT` and a settings row; each harness gets its own word (codex `model_reasoning_effort`, claude `--effort`, opencode `--variant` — `minimal` for low —, hermes `--reasoning`). Codex also runs with the features a recap never uses disabled. | thinking level, reasoning |
| **Locale** | The language of the plugin's own words — the column, the footer, the commands' messages: `en` or `es`. `TAB_RECAP_LOCALE=auto|en|es`; `auto` reads `LC_ALL`, then `LC_MESSAGES`, then `LANG`. Catalogs live in `src/i18n/`; `es` is typed as `Messages`, so a missing key fails the typecheck. | the recap language |
| **Recap language** | The language the recap itself is written in: `en`, `es` or free text (`Português`; letters, spaces, hyphens, ≤ 30 characters, ≤ 3 words). `TAB_RECAP_RECAP_LANG=ui|en|es|<name>`; `ui` follows the locale. Stored on each recap; when it differs from the wanted one the recap is rewritten at once, new excerpt or not. | the locale |
| **Section** | One of a task's recap's seven parts, always all seven, always in this order: `goal · now · needs · done · decisions · next · links` (Goal/Objetivo · Now/Ahora · Needs you/Te necesita · Done/Hecho · Decisions/Decisiones · Next/Siguiente · Links/Enlaces). The id is what the code means; the heading is what a language calls it. An empty section shows `—`. Recaps stored before the fixed structure keep their old Markdown headings (Waiting on you, Key refs, …) until their next rewrite. | a heading's text |
| **Cap** | The most a section may hold, enforced in code, not asked politely: Goal 1 line; Now 3, Needs you 3, Done 5, Decisions 3, Next 5, Links 6 bullets; at most 16 words per line, clipped with `…`. | a length setting (there is none) |
| **Setup modal** | The settings popup (`tab-recap.configure`): rows for the agent (harness or `auto`), its model, the interface language, the recap language and the agents read from their screen; `t` tests the selected agent with one tiny real request, `s` saves to `config.env`. A row an environment variable overrides is read-only and names the variable. Opening it while herdr shows another modal fails with `ui_busy`; the command then prints the CLI equivalent. | the recap modal (`show`) |
| **Hidden** | A tab whose column the operator turned off (`tab-recap.column`, or `h` in the column). It is closed, not reopened, and never counts against the reopen budget; its recaps keep being written. `tab-recap.columns` hides every tab at once; showing one tab again under that blanket exempts it. Remembered in the store (`ColumnVisibility`) and restored at daemon start. | closed by the operator's mouse (that is *given up*) |
| **Extension** | An optional add-on registered in `src/extensions/index.ts` (`FACTORIES`; the built-in git note is the only entry by default). It may contribute notes, a warning and upkeep; the plugin works with none. Built once when a process starts; it reads its own settings through the config getter at call time, so a value edit applies without a restart, but enabling or disabling one takes a restart. | a plugin; a backend |
| **Note** | One labelled line-group an extension attaches to a lane; the column shows it under the lane's header (`⚑ label 2m ago · detail · detail`). It may carry its own **mark** (the glyph before the label, `⚑` when it names none). An extension's `notes()` may receive the tab's lanes and the locale. | a notification we send |
| **Repo** | Which git repository (top-level directory) and branch a lane's working directory belongs to, asked from git by the `LaneRepo` port: a repo (the branch is null on a detached HEAD), no repo, or unknown. Read-only (no optional locks, no fsmonitor), answered asynchronously and cached for a few seconds per directory. | the lane's cwd itself |
| **Git note** | The built-in extension's note under a lane: `⎇ <branch> · N unpushed · M changed` (`⎇ <rama> · N sin subir · M cambiados`), from `git status --porcelain=v2 --branch` in the lane's cwd. Unpushed = commits ahead of the upstream (absent without one); changed = tracked changes, conflicts and untracked files. Nothing outside a repository. Read from a cache: a refresh runs asynchronously, read-only (no optional locks, no fsmonitor), 1.5 s timeout, and is repeated when the worktree's HEAD or index changes or after 5 s. `TAB_RECAP_GIT_NOTE=on|off` (default on), read at call time. | a recap section; the lane's own title |
| **Upkeep** | The housekeeping an extension does on the daemon's resync tick. The column never runs it. | a recap job |
| **Daemon** | The one long-running process: watches herdr, folds observations, dispatches intents. On stop it closes every column in ONE batch (one look at herdr) and waits for it, up to 15 s, before exiting. It beats once a second (`daemon.beat` in the state dir); `ensure`/`start` replace a daemon that is alive but has not beaten for 3 minutes, and the informer subscribes afresh after 5 minutes without a frame or a snapshot. It publishes the plugin version it was **started with** in every tab view; the column ends its meta line with the version of the code on disk (`· v1.5.0`) and, when the two differ, says in yellow `daemon v1.4.1 — restart` (a daemon too old to say shows `v?`). | a *worker* (banned word) |

## The verbs of the fold

| Term | Means |
| --- | --- |
| **Observation** | Something herdr (or the operator) told us: `detected`, `closed`, `status`, `reconciled`, `column-opened`, `column-failed`, `focused`, `requested`, `switched`, `visibility`, `hidden-restored`. The fold's only input. |
| **Intent** | Something the board now wants done: `open-column`, `close-column`, `recap` (of a tab, carrying all its lanes), `publish`, `save-hidden`, `give-up`. The fold's only output. Dispatch turns intents into port calls. |
| **Watch set** | The herdr subscriptions the daemon holds: the global topics plus one `pane.agent_status_changed` per lane. Lives in exactly one file, `watch-set.ts`. |
| **Reconcile** | Replace the board's picture of herdr with a fresh snapshot. A subscription delivers *changes*, never the present, so the snapshot always comes after subscribing. A snapshot is stamped with when it was *requested*: a column opened after that cannot be in it, so its absence is not "gone". Two of our columns in one tab are healed by closing the extra. A refresh of an already-subscribed daemon (the minute tick, a `resync` frame) takes only the snapshot; a new subscription is opened when the watch set changes, the stream ends, or on every 10th tick. |
| **Publish** | Write a tab's view (its lanes and their statuses) for its column to render. |
| **Reopen budget** | How often a column may be reopened after being closed: 3 times in 2 minutes, then the tab is **given up** for 10 minutes. Stops the daemon fighting an operator who means it. |

## Banned synonyms

`summary` → **recap** · `sidebar`, `panel` → **column** · `offset` → **cursor** ·
`worker` → **daemon**. Words that come from the outside world (`away_summary`, a herdr field)
appear only as **string literals** at an adapter's edge, never as our identifiers.
